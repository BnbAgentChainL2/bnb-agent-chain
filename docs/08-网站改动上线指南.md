# 08 · 网站改动怎么上线（给 Codex / GPT 的操作手册）

写给：帮这个项目改网站文案或 UI 的 AI（Codex/GPT）与项目所有者本人
线上地址：<https://bnbagentchain-scan.com>
站点源码：仓库里的 `web/` 目录（纯静态，**没有打包器、没有构建步骤**，改完文件就是最终产物）

---

## 0. 一句话版

改 `web/` 里的文件 → 本地预览确认 → **问过所有者** → 在 `web/` 里跑一条 `vercel deploy --prod` → 线上就变了。

`vercel deploy` 上传的是**本地 `web/` 目录当时的内容**，跟有没有 `git commit`、有没有 `git push` 完全无关。
所以：**改了没部署 = 线上没变；部署了没提交 = 线上变了但仓库里没记录。** 两件事都要做。

---

## 1. 上线命令（唯一正确的那条）

```bash
cd "D:/CLAUDE DODODODODOODODODODODODOODODO/Agent CHAIN/web"
TOKEN=$(grep -m1 "^VERCEL_TOKEN=" ../.env | cut -d= -f2-) \
  && vercel deploy --prod --yes --scope yolo-1ffc --token "$TOKEN"
```

- 必须 `cd web` 之后再跑：Vercel 项目是 link 在 `web/` 上的（`web/.vercel/project.json` → 项目 `bnb-agent-chain`）。在仓库根目录跑会创建出一个**新项目**，域名不会变。
- token 在 `.env` 的 `VERCEL_TOKEN=`（`.env` 已 gitignore）。**不要把 token 打印到终端或贴进聊天。**
- 命令会打印一个 `https://...vercel.app` 的 Production URL，几十秒后 `bnbagentchain-scan.com` 就是新内容。
- `web/.vercelignore` 已经排除 `.env`、`.vercel`、`*.md`、测试 html，不用手动清理。
- 浏览器看不到变化时先硬刷新（Ctrl+Shift+R）；Vercel 侧不需要手动清缓存。

**规矩：部署是对外动作，执行前必须先问项目所有者同意。** 只读、预览、截图随便做。

上线后核对线上（Playwright，会截图到当前目录的 `out/`）：

```bash
cd "D:/CLAUDE DODODODODOODODODODODODOODODO/Agent CHAIN/artifacts/site-shots"
node verify-live.mjs
```

它会打印真实块高是否在递增、页面上还剩几个「读取中…」、控制台有没有报错，并额外截一张**关掉 JavaScript** 的图（抓取器看到的样子，见 §5）。

## 2. 本地预览与自检（部署前必做）

```bash
cd "D:/CLAUDE DODODODODOODODODODODODOODODO/Agent CHAIN"
node artifacts/ui-refresh-reference/serve-preview.mjs      # → http://127.0.0.1:4187/#/overview
```

| 要看什么 | 地址 |
|---|---|
| 中文 | `http://127.0.0.1:4187/?lang=zh#/overview` |
| 英文（**首次访问的默认语言就是英文**） | `http://127.0.0.1:4187/?lang=en#/overview` |
| 有数据的列表/详情页（演示数据，仅本地） | `http://127.0.0.1:4187/?demo=1&lang=en#/blocks` |

预览服务器开着的同时，另开一个终端跑这两个：

```bash
node artifacts/ui-refresh-reference/check-pages-i18n.mjs   # 英文模式下扫 24 条路由 + 各种状态，列出所有漏译的中文
node artifacts/data-check/unit.mjs                          # 网站数据层单测（486 条）
```

`check-pages-i18n.mjs` 的结果写在 `artifacts/ui-refresh-reference/pages-i18n-untranslated.json`。
**`count` 必须是 0**，除非剩下的是用户内容（代币名、符号、agent 简介这类，本来就不该翻译）。

改完 UI 要给所有者**截图**，不要只用文字描述（他明确要求看图）。

## 3. 文案在哪个文件

| 内容 | 文件 |
|---|---|
| 首屏、自己验证这条链、概览、金库、验证者、页脚等**静态文字** | `web/index.html` |
| 列表页/详情页**渲染出来的**文字 | `web/js/ui/pages.js` |
| 表格行里的文字 | `web/js/ui/rows.js` |
| 头部、搜索、链状态条、演示横幅 | `web/js/ui/shell.js` |
| 绑定与格式化产生的文字（单位、状态词） | `web/js/ui/bind.js` |
| **只在 `?demo=1` 下出现的演示数据** | `web/js/ui/demo-data.js` |
| 链接、RPC、合约地址、`rehearsal` 开关 | `web/site.config.js` |
| 样式（金黑配色，别改成终端绿） | `web/css/bac.css`、`web/css/scan-theme.css` |

找一句话在哪，直接 grep 原文：

```bash
grep -rn "要改的那句中文" web/
```

**硬分层规矩，别破坏**：`web/js/data/*` 是唯一碰链的代码，`web/js/ui/*` 绝不发网络请求。

## 4. 改中文 = 必须同步改英文（最容易出错的一条）

中文是**源文本**，英文是覆盖层。英文目录的 **key 就是那句中文原文本身**（空白折叠、NBSP 转空格、trim 之后的）。
**所以你把中文改了一个字，英文 key 就失配，英文模式下那句会原样露出中文。**

三本英文目录：

| 文件 | 管什么 |
|---|---|
| `web/js/ui/i18n-static-en.js` | `index.html` 里的静态文字与无障碍属性 |
| `web/js/ui/i18n-pages-en.js` | `pages.js` / `rows.js` 渲染出来的列表、详情、分页、空状态 |
| `web/js/ui/i18n-runtime-en.js` | 状态提示、搜索、相对时间、图表 tooltip |

改一句话的正确姿势：

1. 改 `index.html` / `pages.js` 里的中文；
2. 到对应目录里找到**以旧中文为 key** 的那一条，**key 和 value 一起改**（key 换成新中文，value 换成新英文）；
3. 元素上有 `data-i18n="xxx"` 的，翻译**优先按这个 key 匹配**，改中文不影响它，但 value 还是要跟着改意思；
4. 新加的句子：中文写进页面 + 三本目录里对应的那本加一条；
5. 跑 §2 的 `check-pages-i18n.mjs` 确认 `count` 没涨。

另外：

- `I.addRules([...])` 里的正则**必须 `^...$` 整节点锚定**（`i18n.js` 会丢弃没锚定的规则），故意不做任意子串替换。
- 用户内容（代币名/符号、agent 简介、URI、日志参数）不翻译。新增的用户值要包 `translate="no"` 或 `data-i18n-ignore`，并且**和周围的 UI 标签分开放在不同节点里**。
- 已排除不翻译的选择器：`.sym`、`.f-x`、`.hexbox`、`.logrow dt/dd`、`.lg-n`。
- 语言优先级：`?lang=` > localStorage(`bac.language`) > **英文**。所以英文目录不是可选项。

## 5. 关掉 JavaScript 也要读得懂

AI 搜索和抓取器不执行 JS，只看静态 HTML。之前外界说「假链」就是因为抓到的全是「读取中…」。

**任何新增的关键论述（我们是什么、怎么自证、披露）必须直接写在 `index.html` 的静态 HTML 里**，不能只在 JS 渲染路径里。
`verify-live.mjs` 会截一张无 JS 的图，用它检查。

## 6. 红线：这些字不许自由发挥

### 6.1 项目方权限披露（措辞随便改，事实要留着）

页面上现在是这一句：

```
项目方可以随时升级桥合约、修改规则，并可随时取走桥池中的全部资金。
```

**网站上的措辞可以自由改写、重排、换更顺口的说法，不用去对合约和 X 文案**（项目所有者拍板；BSC 合约一个都还没部署，早先「四处逐字一致」的要求推迟到部署那天，由 `docs/06-品牌字符串定稿.md` 统一对齐）。

唯一要守的是**事实别丢**：桥合约可升级、规则可改、桥池里的钱项目方可以随时全部取走 —— 这三件事在页面上必须还读得到（首屏或页脚都行）。删掉它会让 §6.2 那批禁止的说法重新变成事实上的暗示。

### 6.2 已经变成假话、禁止出现的说法

- ~~桥池只用于 agent 退出兑付，项目方动不了~~
- ~~进桥的 BAC 永久锁死~~
- ~~桥不可升级~~（「不可升级」只能用来说 `BacNodeFund` / `BacTaxRouter`，**绝不能说桥**）
- ~~退出拿 BNB~~ → 现在是拿**回购来的 BAC**，且不承诺任何金额
- ~~24 小时挑战窗口~~ → 现在是**锚点等待 2 分钟**
- ~~我们的限时签名挑战~~ → 现在是 **ERC-8004 身份**

### 6.3 身份与关系

- **不许写「BNB 官方的 agent」、不许暗示与 Binance / BNB Chain / Flap 有任何关系。** 页脚那条无关联声明必须保留。
- ERC-8004 只能这样说：我们**要求持有** ERC-8004 身份（BSC 注册表 `0x8004A169FB4a3325136EB29fA0ceB6D2e539a432`），并且**保留**「我们要求持有 agent 身份，我们不能证明它是 AI」这句。
- 名称里的 BNB 只表示代币/桥/质押合约将部署在 BNB Smart Chain 上——这条解释不要删。

### 6.4 时间点必须照实

- 只读节点**现在就能跑，没有任何奖励**。
- 质押成为验证者、见证、分 gas 费、出块资格——一律写「**发射后开放**」。不要写成现在就能赚。
- BSC 侧合约还没部署（`site.config.js` 里 `addresses` 全是 `0x0`），所以页面上每一个 BSC 侧的数字都显示「**发射后公布**」。**不许编演示值**，演示数据只允许出现在 `?demo=1`。
- 当前跑的是**演练链**，演练链披露（预置账户用的是公开 Hardhat 测试私钥、币没有价值、发射时重开链）必须保留，直到 `site.config.js` 的 `rehearsal` 改成 `false`。

### 6.5 数字与术语

- 税收基数：Flap 先抽走 **10% 协议费**，`BacTaxRouter` 收到的是税的 **0.90 倍**，再 50/50 分给桥池和节点基金。**「1 BNB 税 → 0.5 / 0.5」是错的**，所有分账文案按扣费后的基数写。
- 术语固定（决策 #18）：锚点的 2 分钟叫「**锚点等待**」，agent 的入场状态叫「**入场验证中**」。**页面上不要再出现「挑战」这个词。**
- 代币 CA `0xA97452d175679B2bF5F25a9a382D22aff39b7777` 是写死在 `index.html` 里的（地址已锁定、发射前没有合约），**不要改、不要挪进 `site.config.js`**，旁边那句「不要往里转账」也要留着。
- 页面上的 `curl` 和 `docker run` 代码块是**从线上 `https://bnbagentchain-rpc.xyz/node.json` 的 `run` 字段逐字复制**的，**不许手改**；只有 `node.json` 变了才跟着改。

拿不准的时候：`docs/decisions.md` 是唯一事实来源，后面的决策覆盖前面的。任何文档和它冲突，以它为准。

## 7. 改完交回什么

1. 改了哪几句：**中文旧 → 中文新 + 对应的英文新**，逐条列出；
2. 中英文各一张截图（改动所在的那一屏，桌面 + 手机宽度）；
3. `check-pages-i18n.mjs` 的 `count`、`unit.mjs` 的结果；
4. 有没有触到 §6 的红线（改写了 §6.1 那句权限披露的话，说一声改成了什么，部署合约那天要按它对齐）；
5. 部署了的话，给出 Production URL 和 `verify-live.mjs` 的输出。

别忘了 `git add` + `git commit`（部署不等于提交）。路径里有空格，所有命令里的路径都要加引号。
