## 3. BSC 侧部署（`01-CONTRACT-SPEC.md` §9 的 ①–⑩）

顺序不能改。④ 和 ⑦ 互相引用（`ChainAnchor` 要桥的地址、桥要锚点地址），
解法是先部 `ChainAnchor`、构造参数里填**按 nonce 预测出来的桥代理地址**，部完再回读核对。

```
①  挖 …7777 靓号 salt，并 Portal.lockSalt(salt, 6)             ← 已完成（决策 #35），T = 0xA974…7777
②  —— 删除（决策 #30：没有 BacVaultUI 链接库了）
③  —— 删除（决策 #31：没有 AgentRegistry 了，入场读 ERC-8004 注册表 0x8004A169…a432）
④  ChainAnchor(预测的桥代理, relayer, admin, vetoKey, 1000e18)   nonce n
⑤  ValidatorStaking(T, anchor, admin)                           nonce n+1
⑥  BacNodeFund(T, nodeFundOwner)                                nonce n+2
⑦a BacBridge 实现合约（无构造参数；构造函数禁用初始化并自己造出 BacBridgeExtension）   nonce n+3
⑦b ERC1967Proxy(实现, initialize(owner, T, ERC-8004 注册表, anchor, watchdog, Portal, PancakeSwap V2 路由))
                                                                nonce n+4 ← 必须正好落在 ④ 预测的地址
⑧  ChainAnchor.setValidatorStaking(⑤)                           nonce n+5，一次性，只有部署者能调
⑨  发射前硬停三项（§1.3）全绿
⑩  BacTaxRouter(T, 桥代理, nodeFund)                            nonce n+6 ← 最后部；这就是发射时的收税地址
```

**桥是代理，这件事要记牢：**

- **所有地方用的都是代理地址**（`DeployBac` 输出里的 `bac.bacBridge`）：`ChainAnchor`、`BacTaxRouter`、中继、
  索引器、网站、SDK、层内创世里的 `L2Bridge.BSC_BRIDGE`。
- 实现合约（`bac.bacBridgeImplementation`）的存储永远是空的，`bacToken()` 读出来是 `0x0`。
  `BacTaxRouter` 的构造函数因此会拒绝它，但别的地方不会替你拦 —— **别把它贴到任何地方**。
- `initialize` 在代理自己的构造函数里执行，同一笔交易，**不存在「代理部出来了但还没初始化」的空档**。

**① 的 salt 为什么一个字都不能改：**`bacToken` 是 ⑤⑥⑩ 的 **immutable**、⑦ 的一次写入存储，值都是本地预测出来的 `T`。
发射时只要 salt 不是逐字同一个，代币就落在别的地址，四个合约全部绑错代币，**没有补救路径**，
整轮重部（④ 的预测随之失效，⑧ 的一次性写入也已经用掉）。

## 8. 层内链上线（bring-up）

顺序是死的：**BSC 合约 → 用真实地址生成创世 → 起 Besu → 起中继 → 起索引器 → 网站指过去。**
每一步都有一件必须当场验证的事，不验证就不许进下一步。

### 8.0 为什么必须是这个顺序

层内 `L2Bridge` 的 `BSC_BRIDGE` 是 **immutable，烧进创世字节码**。创世文件一生成、链一启动，
这个地址就**永远改不了**。所以必须先有 BSC 侧的**桥代理地址**，才能生成创世。
**填代理，不填实现** —— 实现每升级一次就换一个地址，代理地址永远不变，这正是用代理的意义。
反过来做 = 整条链作废，只能换 chainId 重来。

### 8.1 步骤

| 步 | 动作 | 做完必须验证什么 | 不可逆？ |
|---|---|---|---|
| 1 | §3 的 BSC 侧部署 + §6 的发射 + §7 的核验全过 | §7.1 前 12 项全过 | 是 |

### 8.2 每一步的失败长什么样

- **第 6 步 storage 不为零** → 某个系统合约的构造函数写了存储。创世里的合约是**没有构造函数**的，
  写了就意味着上链之后那个槽是 0 而本地是非 0。必须改合约，回到第 4 步。
- **第 8 步块 0 哈希对不上第 7 步** → 起链用的不是我们生成的那个文件。**立刻停机**，不要让它继续出块。
- **第 9 步 `L2Bridge.BSC_BRIDGE()` 不对** → 最可能是把**实现地址**当成了桥。整条链作废（immutable 改不了），
  换 chainId 重来；BSC 侧不受影响。
- **第 9 步 FeeSplitter 没代码** → §0-c 没做完就生成了创世。创世里没有代码的地址**永远加不上代码**，整条链作废。
- **第 10 步锚点提不上去** → 先看 `ChainAnchor` 的 revert 串。最常见的是纪元还没结束就提交，和超发
  （`cumulativeCredited + credited > BacBridge.totalCreditsIssued()`）。

## 9. 上线之后的日常

### 9.1 谁能动钱

- **桥池（BNB 和 BAC，包括 agent 锁进来的 BAC）：桥 owner 能动，随时、全部、没有时间锁。**
  > 项目方可以随时升级桥合约、修改规则，并可随时取走桥池中的全部资金。

  这是决策 #29a 的原话，也是链上 `BacBridge.description()` 返回的第一句。桥 owner 是部署钱包（决策 #33），
  它能 `upgradeTo` 换掉整份桥代码，能 `emergencyWithdrawBnb` / `emergencyWithdrawToken` 把余额一次取光（fork 测试实测：
  取光 BNB 约 9.3 万 gas，取光 BAC 约 10.4 万 gas，升级约 3.9 万 gas）。`renounceOwnership` 被禁用，所以这项权力**放弃不了**，只能转让。
- 每一次升级和提取都会上链留痕：`BridgeUpgraded`（带升级前的实现地址和当时的账本）、`EmergencyWithdraw`（带当时账本上的数和累计提走的数）。
  提取**不改账本**：`shortfall()` 直接给出「账上应有 − 实际持有」的差额，网站要把它和时间线一起显示（决策 #29c）。
- 提取之后会发生什么（fork 测试实测）：新的税照样进来，账本在洞上面继续累加；回购只花**实际在手**的 BNB；
  退出兑付在币不够时失败（先到先得）；把币转回来，洞就补上。
- 暂停开关、看门狗、停机逃生仍然在，但它们**挡不住 owner**，文档和网站不得再把它们说成「最后的兜底」（决策 #29b）。
- **节点基金那一半：`BacNodeFund.owner()` 能提。** 那个合约不可升级、没有别的出口。
- **`BacTaxRouter` 没有 owner**：没有管理员、没有升级、没有提取。它只会把收到的钱推给两个写死的地址（桥代理和节点基金）。
  注意它推的是桥**代理** —— 桥被升级成什么样，路由推过去的钱就归什么样的代码管。

```bash
RPC=https://bsc-dataseed.bnbchain.org
BRIDGE=0x…    # 代理
NODEFUND=0x…
cast call $BRIDGE 'owner()(address)'                          --rpc-url $RPC   # 谁能升级、谁能取走桥池
cast call $BRIDGE 'shortfall()(uint256,uint256)'              --rpc-url $RPC   # 被取走、还没还回来的 BNB / BAC
cast call $BRIDGE 'upgradeCount()(uint64)'                    --rpc-url $RPC
cast call $BRIDGE 'emergencyCount()(uint64)'                  --rpc-url $RPC
cast call $NODEFUND 'owner()(address)'                        --rpc-url $RPC
# 任何签名都不要让私钥出现在命令行、日志或聊天里
```

- **`settle()` / `retryPush()` / `buyback()` / `settleEpoch()` 都是无许可的**，调用者一分钱拿不到。两次 settle 之间路由里会留着没分账的零头，
  这是正常的，`accountedQuote()` 就是它。监控里有一条：**`accountedQuote()` 连续 2 个纪元非零且单调上升** = 没人在调 `settle()`，我们自己调一下。

### 9.2 每一次升级桥合约之前

1. 新实现必须跑完全部非分叉测试 + `BacForkLaunch.t.sol`（它有一条在真实状态上升级、核对账本一个都没动的测试）。
2. 新实现的 `acceptRelease()` 必须在 `BacTaxRouter.PUSH_GAS = 100,000` 之内（现在经代理冷调用实测约 3.6 万 gas）；
   超了，路由推给桥的每一半都会进 `stuckBridge`，直到装上一个放得下的实现。
3. 存储只能在 `__gap` 之上**追加**，不能改顺序。
4. 升级后在 BscScan 上把**新实现和新扩展**各验一次（`verify/bscscan/README.md`）。

### 9.3 必须一直跑的对拍

- 每小时：`TaxProcessor.marketAddress() == BacTaxRouter`。不一致 → 网站挂红条 + **停止一切宣传**。
- 每天：重跑一次 §7.1，尤其看 `state()` 有没有变成 `TaxFree`（这是 `taxDuration` 填错的**唯一**可观测信号，而且一旦出现就无法挽回）。
- 监控告警清单见 `02-CHAIN-SPEC.md` §5.4 与 `00-DESIGN-SPEC.md` §7.1。
