# @bac/watchdog · 常驻自动看门狗

决策 #25a：**锚点等待缩到 2 分钟之后，人工发现窗口等于零。**
剩下的闸门只有两道 —— 每天最多释放 2%–5% 的上限，和暂停开关。
这个进程就是那第二道闸门的执行者：7×24 独立复算链上发生的每一件事，
对不上就自己调 `BacBridge.pause()`，然后把它比较过的每一个数喊出来。

> 等待期是给自动程序用的，不是给人用的。这句话在网站、FAQ、信任表和 X 文案里都要照实写。
> 如果这个进程没跑起来，就**不许**对外说「有等待期保护」。

### 决策 #29 / #29b 之后，这个进程的定位变了（必须照实说）

用户拍板把 `BacBridge` 改成**可升级代理并加 `emergencyWithdraw`**，owner 可随时取走桥池全部资金。
决策 #29b 写明：**`pause()`、停机逃生、watchdog 仍然保留并实现**（对中继私钥被盗仍然有效），
但**不再是最终保障** —— owner 的权限在它们之上。所以：

- 文档和网站**不得**再把这个进程描述为「最后的兜底」；
- 本 README 里凡是写「唯一的闸门」的地方，正确读法是「**在 owner 不作恶的前提下**，
  针对中继私钥泄露这一类攻击的闸门」；
- **合约真的改成可升级之后，`buckets` 这条规则会在 owner 每一次合法升级 / 紧急提取上误报。**
  到那时必须把 `Upgraded` / `EmergencyWithdraw` 两个事件接进 `src/chains.mjs` 的 `bridgeEvents`
  与 `src/rules/buckets.mjs` 的 `flows`。**今天的合约还没改**（`contracts/src/BacBridge.sol`
  仍然是 `contract BacBridge is ReentrancyGuard`，无 owner、无 `emergencyWithdraw`），
  所以在那之前，任何对不上都不是误报。

## 1. 它看什么（五条规则 + 一条只告警的）

| 规则 ID | 看什么 | 独立性从哪来 | 会不会暂停桥 |
|---|---|---|---|
| `anchor_root` | 链上每一个 `AnchorPosted` 里的 `exitRoot` / `l2Block` / `l2BlockHash` / `exitCreditsInEpoch` / `creditedInEpoch` | **不读中继的数据库、不读它的日志、不 import 它的代码**：自己从层内 `ExitBurned` + `CreditsMinted` 重新聚合，用自己那份 merkle 实现算根 | **会** |
| `reconcile` | 层内 vs BSC 的对账恒等式（`03-INTERFACES.md` §3.1 的 `diff`） | 五个链上读数自己拉，公式与网站上公开的那条逐字一致 | **只在 `diff < 0`（超发方向）会** |
| `buckets` | `lockedBac` / `buybackBac` 两个桶 vs BAC 代币的真实余额，以及两个桶的逐笔增量 | 结构性不等式 + 事件溯源的增量对账，不依赖任何人报的数 | **会** |
| `buyback` | 每一笔 `BoughtBack` 的单次上限与滑点 | 在**交易前一个区块**独立再读一次参考价，用没被这笔交易影响过的价格复算 | **会**（上下限永远能判；滑点那一项需要归档节点，读不到就跳过） |
| `release_cap` | 每一笔 `settleEpoch` 的 `pot`，以及滚动 24 小时的释放总额 | 用自己的影子账本（SQLite）重放事件流得到基数，**不需要归档节点** | **会** |
| `cadence` | 中继活性：锚点落后了几个纪元 | 链上 `lastPostedEpoch` | **永远不会**（见 §4） |

每一条裁决都带一个 `compared` 字段，里面是它比较过的**每一个数**。
凌晨三点看到告警的人不需要相信结论，他可以照着那几个数自己复算一遍。

## 2. 探测延迟：指标、实测、推算

指标来自经济模型（`artifacts/sim/RESULTS-buyback.md` §3.3，逐字）：

```
零损失的唯一条件是赶在 120 秒内 veto。
预算：探测延迟 L + 上链延迟 I(≈7 s：签名 1 s + 2 个 BSC 块) + 30 s 安全余量 < 120 s
  ⇒ L ≤ 83 s
工程指标：轮询间隔 ≤ 10 s、端到端探测延迟 ≤ 30 s
```

**本实现达成的值**（`npm test` 里的 `test/latency.test.mjs` 每次都会把它重新打印出来）：

| 项 | 值 | 怎么来的 |
|---|---|---|
| 轮询间隔（快规则） | **5 s**（默认值；配置校验拒绝 > 10 s） | `WATCHDOG_POLL_MS` |
| 关键路径往返次数 | **BSC 5 次 + 层内 40 次 = 45 次** | 实测（含**复核读**与 `pause()` 那一笔） |
| 进程内纯计算耗时 | **≈ 7 ms**（同一台机器上多次运行 6.8–7.4 ms） | 实测（解析日志 + 重算 merkle 根 + 状态机 + SQLite 落盘） |
| 推算探测延迟（BSC 60 ms / 层内 2 ms RTT） | **≈ 0.39 s** | 层内节点在同一个 compose 网络里，RTT 是毫秒级 |
| 推算探测延迟（全部按 60 ms 的最坏情况） | **≈ 2.71 s** | 所有 RPC 都走公网时的上界 |

**端到端账**（从小偷的 `postAnchor` 上链，到 `pause()` 进 BSC 区块）：

```
轮询等待        平均 2.5 s / 最坏 5 s
RPC 可见性延迟  约 1 个 BSC 块 ≈ 3 s
探测 + 复核     0.4 s（典型）/ 2.7 s（全公网最坏）
签名 + 上链     约 7 s（模拟报告给的 I，= 签名 1 s + 2 个 BSC 块）
————————————————————————————————————
合计            典型 ≈ 13 s，最坏 ≈ 18 s
```

**结论：达成 ≈ 13–18 s，指标是 ≤ 30 s，预算上限是 ≤ 83 s。** 两条线都有余量。

三件必须说清楚的事：

1. **进程内那一段是实测的，网络那一段是推算的。** 每次 RPC 往返到底几毫秒取决于当天的
   公共端点，离线测不出来也不该假装测得出来。上表把两段分开列，就是为了让人能用
   自己机器上的真实 RTT 重算一遍。
2. **45 次往返里有一多半是层内的二分查块。** `l2Block(epoch)` 的定义要求二分查找，
   而已经结束的纪元的 `l2Block` 永远不会变（QBFT 即时最终性），所以它被缓存了：
   实测首次 26 次查块，第二次 **0** 次。
3. **13–18 s 赶得上 120 秒的 veto 窗口，但本进程默认没有 veto 权**。见 §5。

## 3. 不许误报：每条规则的三件套

一次误暂停会冻住 `collect`，所以每一条规则都必须有：

**① 容差。** 全部可配（`.env.example` 里有名字与理由）：
- 释放率 `WATCHDOG_RELEASE_TOLERANCE_BPS=50`，外加固定 +1 wei 吸收整除取整；
- 回购滑点 `WATCHDOG_SLIPPAGE_TOLERANCE_BPS=100`，因为参考价读在交易前一个区块上，价格本来就会动；
- 对账的容差不是一个拍出来的数，而是**显式算出来的在途额度**：在途存款（BSC 已 `lock`、
  层内 `seen()` 仍为 false）+ 在途退出（层内 `totalExited` − BSC `totalCreditsExited`）
  + 读数偏斜窗口内已领取的退出积分；
- 慢规则统一从 head 往回退 `WATCHDOG_SLOW_DEPTH=15` 个 BSC 块，躲开重组。

**② 跳闸前的复核读。** 同一件事**换一个数据源**重算一遍：锚点从第二个 BSC RPC 读
（这顺带排除掉「BSC 重组掉了那笔 `postAnchor`」这种幻影 —— 测试里有这一条），
层内从第二个层节点读。两次都成立才发交易。
复核本身失败（第二个端点挂了）既不算坐实也不算撤销：单子留在 `pending_confirm`，
下一轮继续，同时立刻告警 —— 因为这时候看门狗是瘸的。

**③ 把比较过程原样记下来。** `compared` 进日志、进 SQLite 的 `findings` 表、进 webhook。

### 已经写进测试的「必须不跳闸」清单

- 层内停过块的**空纪元**（`exitRoot = 0`、`exitCount = 0`、`l2Block` 与上一纪元相同）；
- 被 `veto` 的纪元的叶子**原样重报**进下一个锚点（`03` §1.3）—— 测试里有一条对照组：
  去掉那条 `AnchorVetoed` 事件，同一个锚点就该被判为伪造。这证明重报逻辑是承重的；
- 历史余额读不回来（Besu `--bonsai-historical-block-limit=512` ≈ 25.6 分钟）→
  `feeBurnedInEpoch` / `circulating` 一律跳过，它们本来就是信息字段（修订 #30）；
- 公共 BSC RPC 不是归档节点 → 回购的滑点那一项跳过，只保留上下限检查；
- 有人直接给桥转了 BAC（真实余额高于账面）→ 只提醒「可以调 `sweepUntrackedBac()`」；
- 在途存款让对账 `diff` 变正 → 只告警；
- 中继停摆一整天 → 只告警。

## 4. 往哪边倒，以及为什么

**往「宁可暂停」倒，但只对能算清楚的规则这么做。** 两边的代价并不对称，而且和直觉相反：

- **一次误暂停是可以立刻撤销的。** `unpause()` 就在同一把钥匙上，`pausedCumulative`
  只累计**真正暂停过的秒数**（`BacBridge._pauseUsed()`）。所以误报的代价是
  「几分钟 `collect` 停摆 + 从 21 天累计额度里扣掉这几分钟」，**不是七天**。
  （七天是 `PAUSE_LEN`，即没人管的情况下它自己到期的时间；不是不可缩短的时长。）
- **一次漏报是不可逆的。** 120 秒之后锚点 FINAL，小偷的 `claimExit` 当场按
  `(buybackBac − owedTotal) / creditsOutstanding` 把**整个未占用的资产桶**锁成自己的债权，
  积分当场销毁。这之后 `pause()` 撤不回任何东西，只能延后。

所以：

- **算得清的规则跳闸**：锚点根、对账的超发方向、两个桶、释放率上限、回购的上下限与
  （能读到参考价时的）滑点。
- **算不清的规则只告警**：中继活性、行情、信息字段、需要归档节点而读不到的项、
  对账的正方向。

**中继停摆为什么绝不跳闸**，单独说一次：中继停了是可用性问题，没有一分钱被多放出去。
这时候 `pause()` 只会把「退出慢」升级成「退出停」，还白白吃掉 21 天额度里的一段 ——
而额度耗尽本身就是停机触发 5。方向是 fail-safe，但不该由一次误判去触发它。

## 5. 已知的能力缺口（必须照实说）

**① `pause()` 不是零损失路径。** 模拟报告 §3.2 算得很清楚：`pause()` 只停 `collect`，
**撤销不了已经锁定的 `owed`**。`PAUSE_LEN = 7 天` / `MAX_PAUSE_TOTAL = 21 天` 一到期，
按每天 2%–5% 继续领，把整个桥领空只是时间问题（2%/天：21 天搬走 34.6%，90 天 83.8%）。
零损失的唯一条件是**在 120 秒内 `veto`**，而 `ChainAnchor.veto()` 今天只允许
`admin` 或 `vetoKey` 调用，且 `01-CONTRACT-SPEC.md` 写明 `vetoKey` 是冷钥 —— 冷钥在 120 秒内签不出来。

本实现的处理：`WATCHDOG_VETO_PRIVATE_KEY` 留空时只 `pause()`；运维如果接受报告 §3.3 B6 的
建议、把 `vetoKey` 改成交给这个常驻进程的热钥，填上它之后看门狗会**先 veto 再 pause**
（测试覆盖了「还在 120 秒内 → veto + pause」与「窗口已过 → 只 pause，不白发一笔必然 revert 的交易」）。
代价也要写明：热钥被盗 = 可以连续否决锚点，7 次触发停机 —— **这是拿 DoS 风险换盗窃风险**。

**② 真正的止损动作是 `revokeEpochOwed`，而它需要人按。** 合约里这个函数只有 watchdog
能调、只在暂停期间能调、只能作废不满 `OWED_MATURITY`(14 天) 的债权。它会**误伤**同一个
锚点纪元里的诚实退出者（他们要凭修正后的根重新 `claimExit`），所以本进程**不会自动调用它**。
它是运维手册里的一步，不是看门狗的自动动作。

**③ 层内只有一台节点。** `LAYER_RPC_2` 留空时，锚点根的复核读退化成「隔一会儿再读同一台」，
它能排除瞬时读取错误，**排不掉节点本身说谎**。这与信任表第一行「出块、中继、索引同一个
信任域」是同一件事，不能因为多了一个看门狗进程就淡化它。启动时会为此打一条 warn。

**④ 回购的滑点检查需要归档节点。** 公共 BSC RPC 基本都不是。读不到时那一项跳过
（日志里写明 `referenceAvailable: false`），只剩单次上下限那两条硬检查。
想让这一项真正生效，得挂一个能读历史状态的 BSC 端点。

**⑤ 看门狗和中继、出块节点在同一台机器上。** 整台机器被拿下时它保护不了任何东西。
这条写在 `00-DESIGN-SPEC.md` §2 的信任表里，看门狗不改变它。

## 6. 跑起来

```bash
cd watchdog
npm install                  # ethers 6.13.4，没有别的依赖
cp .env.example .env         # 填地址与私钥；.env 在 .gitignore 里
npm test                     # 99 个测试，全离线，不连任何网络
npm run once                 # 跑一轮就退出（演练 / 巡检脚本用）
npm start                    # 常驻
```

容器里的跑法见 `chain/docker-compose.yml` 的 `watchdog` 服务和
`chain/OPERATIONS.md` §9。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常退出（`--once` 跑完，或收到 SIGTERM） |
| 2 | 配置有误，没启动 |
| 3 | **已跳闸**。桥已经（或本该）被暂停，进程故意退出，等人来看 |
| 4 | 启动自检没过（多半是那把钥匙不是 `BacBridge.watchdog()`） |

跳过闸之后，重启时会**立刻再退出一次**（还是 3），直到有人处理：
把 `findings` 表里那几行的 `state` 改成 `cleared`，或者临时设 `WATCHDOG_RESUME_AFTER_TRIP=true`。
compose 里因此用 `restart: "on-failure:3"`：撞三次就停在那里，`docker ps -a` 上看得见。

### 启动自检（不过就不启动）

1. `BacBridge.watchdog()` 是不是本进程手上这把钥匙的地址；
2. 链上的 `EPOCH` / `EPOCHS_PER_DAY` / `ANCHOR_WAIT` / `MIN_BUYBACK_BNB` / `MAX_BUYBACK_BNB` /
   `MAX_BUY_SLIPPAGE_BPS` 与 `src/constants.mjs` 里那份是否逐个相等；
3. 两个 BSC 端点和层内端点是不是都读得通；
4. 配了 `WATCHDOG_VETO_PRIVATE_KEY` 的话，它是不是真的就是 `ChainAnchor.vetoKey()`。

一个「跑着但按不动刹车」的看门狗比没有看门狗更糟：运维会以为桥有保护，
于是把 2 分钟等待当成安全边界对外讲。所以这几条没有「警告后继续」这个选项。

## 7. 落盘的东西（重启不丢进度）

SQLite（`WATCHDOG_DB`）里有五张表：

| 表 | 作用 |
|---|---|
| `cursor` | `bsc_anchor` / `bsc_bridge` 两个游标。重启后接着扫，不重复不跳过 |
| `ledger` | 影子账本：上一次快照的五个标量 + 滚动窗口基数。释放率上限的基数就从这里来 |
| `carry` | 被 VETOED / DISPUTED、等着被重报的纪元。**丢了它就会把合法重报误判成伪造** |
| `release_log` | 逐纪元的释放额，滚动 24 小时的上限靠它 |
| `findings` / `trips` | 发现的生命周期与每一次跳闸的记录 |

**发现的一生**，以及它为什么必须落盘：

```
CRITICAL → pending_confirm（先落盘）→ 复核 → pending_trip（先落盘）→ pause() → tripped
                                        └→ 不成立 → cleared
```

进程在任何一步被 kill，重启时 `resume()` 会捡起来接着走：
`pending_trip` **直接跳闸、不重新探测**（重新探测要多花一个完整的轮询周期，
而 120 秒的窗口里这是致命的）；`pending_confirm` 重跑一遍规则走正常复核。
`test/restart.test.mjs` 测的就是这两条，外加「误报不会在重启后被翻出来」「游标落盘」
「重报集落盘」。

## 8. 为什么 merkle 的实现是自己写的一份

这是仓库里的第四份（中继 / `@bac/agent-sdk` / `@bac/node-cli` / 这里），而且是**故意**分开写的：
看门狗的全部意义就是不相信中继报的东西，import 它的代码等于让中继的一个 bug 在两边同时出现，
比较永远相等，`anchor_root` 这条规则结构上失效。

代价是四份实现有漂移的风险，所以 `test/ids.test.mjs` 里有一条测试会 import 中继那份，
用 200 组随机叶子逐字节对比两边算出来的根。仓库里没有 `relayer/` 时（容器里只挂了 watchdog）
这条测试跳过。
