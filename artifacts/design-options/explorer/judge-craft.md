# 评审：视觉完成度与桌面构图

评审范围只有一条：**画面做没做完，1440 / 1920 的版面有没有用满，栅格纪律、字阶、表格、密度、动效、390px**。
不评信息架构是否正确，不评文案，不评合约逻辑。三个方案的截图逐张看过，CSS 逐个量过。

| 方案 | 分数 |
|---|---|
| explorer（方案一 · 浏览器优先） | **8.5** |
| console（方案二 · 机房操作台） | 7.5 |
| hybrid（方案三 · 分页式应用） | 7.0 |

**胜出：explorer**

---

## explorer — 8.5

量到的：`--maxw:1660px`，`--gut:20px`，body 13px，`font-variant-numeric:tabular-nums` 开在 body 上（三个方案里只有它和 console 是全局开的）。
`.grid-main` 在 1440 是两列，`@media(min-width:1520px)` 升三列 `1.05fr / 1.05fr / .8fr`。

做得好的：

- **1440 → 1920 是"长出一列"，不是"拉宽"。** 1920 时第三列真的出现了内容（tail -f 实时流 + NODE-01 机房面板），不是把两列表格抻长。这是这套里唯一一个把多出来的 480px 换成信息的方案。
- **表格是三家里最扎实的。** 交易页 1440 下 19 行可见，行高 33px，数字列全部右对齐，单位（BAC / gwei）用 9.5px dim 色跟在数字后面不抢位，状态用 chip。`th` 9.5px + `.12em` 字距 + `--dim-2`，和 12px 的 `td` 拉开了层级。
- **字阶是真的有五级**：section 标题 14px/600 + 拉丁副题 → 状态格数字 16.5px → 正文 13px → 面板头 10.5px 加字距 → 元信息 9.5px。靠"字号 + 颜色 + 字距"三个变量同时走，不是只靠颜色。
- **抽屉详情**（shot-drawer-tx / shot-drawer-block）压半屏、背景变暗、左边列表还在——桌面上这是对的，比 hybrid 整页跳转保留更多上下文。
- **图表段是唯一成型的**：三张图并排，有图例、有轴标签、有 30 天合计。Agent 目录 4 列卡片带 sparkline，密度高但每张卡都有呼吸。
- **390px 稳。** 状态格 8→2 列，头部保留了 `1,234,567`（console 丢了），A/B/C 分账卡竖排后 10%/90% 条仍然读得出，表格有 `.tw{overflow-x:auto}`。

扣分的：

- **字阶没有顶。** 全站最大 16.5px。1440 一屏扫下去，所有东西的"重要度"差不多，缺一个视觉落点。
- 1920 下 1660 的上限留了左右各 ~130px 空边。作为版心可以辩护，但用户的原话是"电脑版没做好"，这口气是要满。
- 1440 下 8 个状态格每个 175px，`TPS（近 100 块）` 这类标签已经贴着 ellipsis 的边。

## console — 7.5

量到的：`.grid{max-width:2160px;padding:14px}`，`.ops` 三列 `3.1fr/5fr/3.3fr`，高度 `clamp(534px, calc(100vh - 196px), 800px)`，`@media(min-width:1800px)` 改成 `3.2/5.2/3.2` 且高度上限抬到 860px。

做得好的：

- **1920 的答案是三家里最好的。** 2160 版心 + 14px 边距 = 真·满屏，而且有专门的 1800+ 规则去加宽中列。更关键的是 `.ops` 锁视口高：实时流、区块、交易、机房面板、纪元锚点**一屏之内全在**，不用滚。这才叫操作台构图。
- 10 格状态导轨横贯整个宽度；区块表里 `54,222/20,000,000` 带分母 + `0.27%` 占比列，是这套里最聪明的一处密度。
- **终端气质最足**：`tail -f /bac/actions`、PEERS/TXPOOL/DISK 条、琥珀色纪元时间轴（20716 FINAL / 20717 POSTED·挑战中 / 20718 进行中）。用户挑的就是这个主题，它最像。

扣分的（都是"没做完"的硬伤，截图里直接看得见）：

- **最后一行被粘底切掉。** shot-hero 里实时流最后那条 `22:41:12 LAYER LIST agent #31 上架…` 和 `未锚定的条目只来自官方节点…` 叠在一起；区块表最后一行 `#1,234,562` 被分页条压掉半行。没有渐隐遮罩，看起来就是渲染 bug。390px 上同一个问题更明显。
- **10%/90% 那个条，10% 格窄到把标签截成"验…"。** 新规则里最要紧的那个数字，是这套里做得最糙的一格。
- **层级最平。** 每个面板同样的 1px 边、同样的 10.5px 面板头，最大字号 16px。1920 下左列变成一面 860px 高、粗细完全一致的文字墙——那是噪音不是密度。
- **390px 丢了链头高度。** 顶栏 `.led{font-size:0}` 之后只剩三个点，`HEAD 1,234,567` 不在；状态导轨横向滚动，截图停在 TPS，最新区块在视口外。手机上静止状态看不到这条链的头号数字。

## hybrid — 7.0

量到的：`--app-max:1760px`，固定头 `48 + 34 + 56 = 138px`，最大字号 19px（详情页 h1）。

做得好的：

- **单页最强的两张在它这里。** 金库页（税流图 + 链上读数 KV + 30 日进金库柱图 + 金库事件表）和 Agent 目录（42 行全表 + 右侧 24h 活跃热条）是整套素材里构图最完整的两块，没有空地。
- **唯一有字阶顶端的**：19px 详情标题 + 面包屑 + 每条路由自己的页头。explorer 和 console 都没有这个。
- 交易表的方法 chip（`转账` / `publish(string)` / `settle(uint64)` / `exit(uint256)`）给表格带来了真正的扫读纹理。

扣分的：

- **空地是它在这条评审线上最大的问题。** 交易详情页（shot-tx-detail）左边 KV 只占 55%，右边"事件日志（0）"是空面板，再往下到页脚之间大片全黑。1440 下一屏里有近四成是空的。1920 下概览两张表被抻开，`方法` 和 `区块` 之间裂出大片空隙。
- **行密度最低**：区块行 44px、出块者占两行，1440 下只有 7 行可见（explorer 12 行，console 6 行但一屏还塞了另外四个面板）。
- 138px 的固定头，1440 下还没开始看内容就先吃掉 10% 的视口；390 下是 172px / 844px。
- **验证者页结尾四段大白话堆在一起**（奖励怎么来的 / 阶段 2 的 50% 怎么强制 / 罚没 / 抓得到抓不到），没有任何层级，是整套里唯一一处纯文字墙。
- **390px 表格漏字段**：区块表横向溢出、`scrollbar-width:none`、无边缘渐隐，`手续费` `状态` 两列直接跑出屏幕外，看不出还能滑。

## 赢家还要改的（只按本条评审线）

1. **把字阶的顶端补上。** 全站最大 16.5px 是不够的。首屏 `最新区块` 和每个 section 的头号数字给到 22–26px，让 1440 和 1920 各有一个视觉落点。
2. **1920 别留空边。** `@media(min-width:1800px)` 把 `--maxw` 抬到 ~1880 或直接放开；防止表格被抻散的办法是限 `目标/哈希` 列宽，不是限页宽。
3. **1440 的 8 格状态条把标签挤到了 ellipsis 边缘。** 要么 ≤1500 改 6 格 + 2 格提升，要么把 `.sg i` 的字距从 `.11em` 降到 `.06em`。
4. **首屏面板锁视口高**（抄 console 的 `clamp(100vh - chrome)`），让折线永远落在行边界上，不要半行被切。
5. **所有可滚面板在页脚线之前加一层底部渐隐遮罩**——现在表格是硬贴着分页条断的。
6. **390px 的状态格现在是 4 行 ~330px 才见到数据。** 前两格做成整宽强调，剩下六格压成紧凑两列表。
7. **图表三"每日 gas 费去向"的图例要跟上新规则**：现在是单序列 `官方基金会 90% / 验证者池 10%`，得改成两条序列——官方节点出的块 10/90，验证者出的块 50/50——否则阶段 2 一上线这张图就是错的。

## 从输方身上移植

**从 console 拿：**
- `.ops` 的视口锁高操作带（`clamp(min, calc(100vh - chrome), max)`），用在 explorer 的首屏。
- 区块表的 `占比` 列 + 行内 `/20,000,000` 分母写法。
- ≥1800px 主动加宽中列的那条规则。
- **琥珀色纪元/锚点时间轴**（20716 FINAL / 20717 POSTED·挑战中 / 20718 进行中）——整套素材里表达力最强的一个图形，explorer 现在没有等价物。
- gas 费对账那一排四格等式（`官方节点已收 − 已转入分账合约 = 差额`），中间真的排出 `−` 和 `=` 两个字符。

**从 hybrid 拿：**
- **整张金库页的构图**：税流图 + 链上读数 KV + 30 日进金库柱图 + 金库事件表（RevenueSplit / Withdrawn / ReleaseReceived 带 BSC 链接）。这比 explorer 现在的金库页完整。
- **Agent 目录改成全表 + 24h 活跃热条**，卡片版留给单个 agent 的详情。
- 交易表的方法 chip（`publish(string)` / `settle(uint64)` / `exit(uint256)`）。
- 单笔交易里的「这笔费用去了哪」小面板：把 10%/90% 换算成具体 BAC 金额并排出来。
- 独立详情路由的面包屑 + 19px 标题（抽屉留着，但深链接进来时要有这一版）。
