# 评审：视觉完成度（craft）

镜头只有一个：**这看起来像不像一个有功底的设计师做的。**
只看字阶是否真实存在、间距节奏与对齐、表格排版、金色是否克制、空状态/发射前状态的完成度、
图标与 chip 的一致性、1440 与 1920 是「排过版」还是「被拉宽」。功能、信息架构、文案一律不计分。

被否掉的旧皮肤：`web/css/app.css` —— 绿底黑终端、全站等宽。
三个新皮肤都换成了 `#0B0E11 / #181A20 / #1E2329 / #2B3139` + `#F0B90B`，
正文改无衬线、等宽只留给哈希和对齐数字（`--sans` / `--mono` 令牌三家都有）。
**配色和字体混用这两条，三家都算修好了。** 差别在后面的手艺。

---

## 1. exchange —— 8 / 10 · 胜出

### 好在哪

- **字阶是真的在用，不是写在注释里。** 截图里中文标签是无衬线、数字和哈希才是等宽；
  `font-family:var(--mono)` 33 处全是定点覆盖，不是全局。`tabular-nums` 15 处。
- **表格排版是三家里最好的。** `shot-blocks.png`：交易 / GAS 用量 / 占用 / 手续费四列全部右对齐、
  等宽、tnum 对齐；表头是拉开字距的灰色小写大写；行高 61px 有呼吸；右上角分段筛选（全部 / 官方节点 / 验证者）
  带「422 块」计数。
- **详情页是三家里排得最像产品的。** `shot-block-detail.png`：面包屑 → H1 + 绿色「层内已最终」药丸 →
  整条哈希独占一行 → 金色 BLOCK 标 + 两个 API chip → 左右两栏。`gas 用量` 那行还内嵌了一条占用量进度条。
- **1920 是排过版的**（`shot-wide.png`）：容器 1560 居中，hero 左栏底边（y≈520）和右侧 CHAIN HEAD 卡底边（y≈525）
  几乎齐平，不是把内容拉宽了事。
- **「一笔交易税的去处」是一张真正设计过的图**，不是把数字堆成三行。

### 还是很业余的地方（必须改）

1. **金色在表格里被喷了。** `shot-blocks.png` 里区块号整列是金的，`分账` 列每一行又挂一个金色描边的
   `10 / 90` chip —— 12 行就是两条金色纵列。而且这个 chip 在 422 行里**值永远一样**，
   一个永不变化的值不配拿走强调色。
2. **`链上读数` 里用了 `├` `└` 制表符画树。** 金库页那两行「├ 累计 → 桥池 / └ 累计 → 节点基金」
   是字面意义上的终端 ASCII art —— 正是用户嫌弃的那个味道，出现在一个号称无衬线优先的皮肤里。
3. **发射前状态没设计过。** `shot-prelaunch.png`：`发射后公布` 被排在 22px 的主数位置上，
   指标条里连着出现 6 次，成了一堵字墙；而同一张「链头」卡里 `累计交易` / `累计合约` 用的是 `–`，
   `桥池余额` 用的是 `发射后公布` —— **一张卡里两套空值写法**。
4. **字阶上半段是塌的。** `--t-hero:26` / `--t-datum:26` / `--t-h1:24` 三级挤在 2px 内，
   上半段的「层级」是假的。另外 `font-weight:620 / 650 / 660 / 680` 共 11 处，
   系统字体基本会吸附回 600 或 700，等于白写。
5. **图表配色不统一。** 金库页「近 30 日进金库」是绿柱，全站其他图表都是金柱。
6. **演示条是紫色的。** 令牌里有 `--violet`，但页面主色系里没这个色相，那条横幅读起来是站外来的。
7. **同一个 10/90 关系，三页三种配色**：区块详情是绿+金，验证者页是紫+金，金库页是绿+金块。
8. **移动端头部四行才到导航**（品牌 / LED / HEAD 药丸 / 搜索），且横向滚动的导航把「验证者」
   齐刷刷切一半，没有渐隐遮罩，看着像坏了。
9. 区块详情页 H1（22px）和它下面那条 17px 白色等宽全哈希在抢视线，两个都想当主角。

## 2. editorial —— 7 / 10

### 好在哪（有几样三家里唯一）

- **唯一一个 hero 标题是「设计」出来的，不是「调大」出来的。** 三行分别是
  重白 / 中灰 / 金色 `agent` + 灰，字重、颜色、字号三个维度同时在做层级。
  这是全场最像设计师手笔的一处。
- **字阶最完整**：`--t-micro 10 → --t-5xl 62`，11 级，而且截图里是真的在用。
- **编号分节尺**（`01 链的当前状态` / `02 正在发生` / `03 最近三十天` / `04 逐条记录`），
  右侧还配了右对齐的分节说明。三家里只有它有这套版面语言。
- **1920 最从容**（`shot-wide.png`）：标题放大到 ~62px，导航、指标条、卡片左边缘全部对齐在 x=200，
  页脚也是，从上到下一根轴。
- **发射前状态是三家里最好的**（`shot-hero-pre.png`）：hero 的四个读数里，
  `活跃 AGENT` / `桥池余额` 把 `发射后公布` **降到 13px 次级灰**，不占主数位置。这是正确解法。

### 致命伤

1. **哈希被折成两行。** `css/app.css:359` —— `.tbl td.wrap{word-break:break-all;white-space:normal}`。
   后果在三个页面都能看到：概览「最新交易」的 `0xaaa8063fa5f…` / `be369e`、
   金库事件的 `0x1c61b4…` / `1e58`、验证者节点列表的 `0x3c9a5f…` / `0d1e`。
   **哈希折行是整个评审里最业余的一处**，exchange 有 17 条 ellipsis 规则、neon-gold 有 25 条，
   editorial 在表格里选择了折断。
2. **hero 正文的加粗被折行劈开**：「…我们能证明入场的是程序，**不能证** / **明它是 AI**。」
   —— 1440 和 1920 都这样，不是偶发。
3. **`待锚定` 是灰底灰字灰描边药丸**，在灰行上几乎读不出来；exchange 给了琥珀色圆点，它把语义色扔了。
4. **自己打自己**：hero 的空值规则是对的，但头部指标条里 `活跃 agent` / `验证者` / `桥池余额`
   还是把 `发射后公布` 排在主数字号上。一个皮肤里两套空状态标准。
5. 图表 Y 轴刻度是 `5.3 / 2.7 / 0` —— 自动算的，没有人排过。
6. **移动端把 NODE / RELAY / INDEX 三个状态灯整个丢了**（`shot-mobile-top.png` 顶部三行里没有）。
7. 眉题「建在 BNB SMART CHAIN 之上 · CHAIN ID 56777 · BESU QBFT」折行后「阶段 1」孤零零掉到第二行。

## 3. neon-gold —— 6 / 10

### 好在哪

- 字重只用 500 / 600 / 700 / 800 四档，是三家里最干净的。
- `text-overflow:ellipsis` 25 处，省略纪律最好，表格里没有折断的哈希。
- **方法 chip 按类型分色**（`shot-txs.png`：swap/quote/announce 蓝紫、合约部署 绿、转账 蓝、exit/withdrawCredits 金），
  比另外两家的一锅端有信息量。
- 纪元倒计时的金色进度扫描、验证者页 A/B/C 三条分账比例条，都是有想法的零件。

### 为什么只有 6

1. **1920 不是排版，是拉宽**（`shot-wide.png`）：hero 卡一直铺到 x≈1815，
   左边文字栏在 x≈820 就结束了 —— 中间近 1000px 是空的，只有散落的星点。
2. **星座连线背景 + 线条机器人 = 现成的「AI 科技感」素材。** 机器人在 hero 和 NODE-01 面板各出现一次；
   **移动端更糟：机器人被放在标题上面**（`shot-mobile-top.png`），手机用户第一眼看到的是一个卡通机器人，
   不是这条链是什么。装饰压过内容，这正是「美术很差」的典型症状。
3. **头部指标条通栏铺到 x=0，下面所有卡片却在 1720 的容器里**（第一格从 x≈10 开始，`链状态` 卡从 x≈105 开始）
   —— 头部和正文的左边缘对不上。
4. **发射前状态三家里最差**（`shot-prelaunch.png`）：`发射后公布` 以主数字号出现在头部指标条、
   在「桥与积分」面板里顶掉 `9.14`（于是面板主数读作「发射后公布 BNB」）、在金库和验证者右栏里成排出现，
   **一页里同一个六字短语重复约 25 次**，看上去像模板炸了。
5. **hero 的四个统计卡是按内容撑宽的，不是栅格**（宽度 138 / 160 / 165 / 165），右边缘跟任何东西都不对齐。
6. hero 正文在灰色句子中间插白色加粗，和 editorial 一样的毛病。
7. `tabular-nums` 只有 1 条规则（覆盖 `.n / .tbl td.n / .tbl th`），非表格里的数字全靠等宽字体兜底。

## 结论

**胜出：exchange。**

它在本镜头的四个硬项上赢：表格排版、详情页版面、1440/1920 的构图、以及最少的「装饰性废话」。
editorial 的 hero 字体处理和编号分节是全场最高水准的两件东西，但它在表格里折断哈希、
在正文里劈开加粗，craft 的下限塌了；neon-gold 把预算花在了星点和机器人上，
1920 空了一大块，发射前状态直接崩，是三家里最「像素材站」的一个。

**从落选者移植进 exchange：**

| 来源 | 移植什么 |
|---|---|
| editorial | hero 三行标题的字重+颜色+字号三维层级；`01–04` 编号分节尺和右对齐分节说明；11 级字阶（用来修 exchange 塌掉的上半段）；hero 把 `发射后公布` 降到次级 caption 的空状态规则 |
| editorial | 税流图的几何：10% 协议费块与「进金库」同高左贴、色块图例、0.45/0.45 更正用金色 callout —— 比 exchange 那个悬空斜纹块干净 |
| neon-gold | 交易表的方法 chip 分色；25 条 ellipsis 的省略纪律；移动端三个状态灯折叠成三个圆点的紧凑头部；纪元金色进度扫描 |
| neon-gold | **不要移植**：星座连线背景、机器人吉祥物、通栏指标条 |
