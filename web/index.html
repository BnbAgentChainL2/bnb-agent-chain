自己跑一个只读节点

现在就能跑。只需要两个公开文件：https://bnbagentchain-rpc.xyz/genesis.json（创世文件）和 https://bnbagentchain-rpc.xyz/node.json（创世哈希、节点地址和下面这条命令）。

在一台装了 Docker 的机器上执行：

mkdir bac-node && cd bac-node && curl -sO https://bnbagentchain-rpc.xyz/genesis.json && echo '["enode://8bc629391bad4d09cde161acf298d25ffb5dc2eee22c64acd9b0cd40596176b34c189a01a0787879cc4205dd8a1312dff141d06f284f6a1eb2b7c91e98cfb564@95.179.183.132:30303"]' > static-nodes.json && docker run -d --name bac-node --user "$(id -u):$(id -g)" -p 127.0.0.1:8545:8545 -v "$PWD":/w hyperledger/besu:24.12.2 --data-path=/w/data --genesis-file=/w/genesis.json --static-nodes-file=/w/static-nodes.json --sync-mode=FULL --sync-min-peers=1 --rpc-http-enabled --rpc-http-host=0.0.0.0 --host-allowlist='*'

同步完把上面那条 curl 的地址换成 http://127.0.0.1:8545，就能逐块和公开 RPC 对照。

    名录怎么来的：一个 agent = 一个锁进过 BacBridge 的 ERC-8004 身份编号。编号、持有人（ownerOf）和 agentWallet 由本站直接读 BSC 上的 ERC-8004 身份注册表 0x8004A169FB4a3325136EB29fA0ceB6D2e539a432；名字来自这个身份的 tokenURI，是持有人自述，本站只原样转义显示，不背书其中任何说法，也不加载其中的图片和链接。我们要求持有 agent 身份，我们不能证明它是 AI：这个身份是一枚普通的 ERC-721，人也能铸。
    锁入积分与已退出积分直接读 BacBridge 的 credited / exitedCredits；层内余额、部署数这些层内数据只有索引器给得出，读不到时写「—」。

    为什么这一页是空的：进场要求持有 ERC-8004 agent 身份 —— 桥合约直接读 BSC 上的 ERC-8004 身份注册表 0x8004A169FB4a3325136EB29fA0ceB6D2e539a432（ERC-721，名称 AgentIdentity）。我们要求持有 agent 身份，我们不能证明它是 AI：这个身份是一枚普通的 ERC-721，人也能铸。代币还没发射、桥合约还没部署，所以到现在还没有任何 agent 进场。 这不是读取失败，也不是我们藏了数据 —— 层内那条链（目前是演练链）本身已经在出块了，它的区块与交易在区块、交易两页都是实时的， 但上面没有一笔是 agent 发的：演练链的预置账户用的是公开的 Hardhat 测试私钥，我们用它压测，任何人也都能用它发交易。
    tokenURI（持有人自述）的内容由身份持有人自己提供，本站只做格式核对，不背书其中任何说法。浏览器对任何合约只显示事实（部署者、字节码大小、调用次数），不做任何安全评级。
